# 企业访谈准备 Skill

> 不再拿一份通用问题清单走遍所有企业：在拜访前生成与行业、部门、岗位和具体流程匹配的访谈计划。

当前版本是 **Codex 本地个人实验版**，尚未发布到 GitHub，也未验证 Claude、Hermes 或其他 Agent 平台。
因此目前没有可用的 `npx skills add OWNER/REPO` 公开安装命令。

## 安装

将完整目录安装到 Codex 的本地 Skill 目录：

```bash
cp -R enterprise-interview-preparation ~/.codex/skills/
```

确认入口文件存在：

```bash
test -f ~/.codex/skills/enterprise-interview-preparation/SKILL.md
```

安装不会联网，不需要 API Key，也不会自动联系员工、创建会议、录音或上传企业材料。

## 适合

- 判断应该访谈哪些角色以及为什么；
- 为不同角色准备开放主问题与动态追问；
- 将问题绑定到能改变的决定和最小证据；
- 在总时间、最多人数和角色不可访问等限制下生成最小可行访谈组合；
- 预先标记管理岗、执行岗和系统岗之间可能出现的待验证分歧；
- 准备录音/材料同意、现场边界和不能承诺的事项；
- 输出可以进入企业AI诊断总档案的计划记录。

## 不适合

- 现场逐题采访一名员工并生成流程卡；
- 分析已经收到的会议、SOP、表格和截图；
- 决定使用规则、工作流、RPA、AI或Agent；
- 直接安排会议、联系员工、录音、上传文件或开发系统。

## 你可以直接这样说

- “使用企业访谈准备 Skill，为连锁零售门店客诉流程生成访谈对象、分角色问题、追问路线和最小材料清单。”
- “下周要访谈制造企业采购部，目的是判断采购申请到下单有哪些改造机会，帮我准备访谈方案。”
- “我只知道客服主管说重复工作很多，先帮我确定应该访谈哪些岗位，以及每类岗位重点问什么。”
- “根据这份已知背景准备访谈，但不要现在判断该上工作流、RPA还是Agent。”
- “只有3小时、最多访谈4人，主管和一线对系统覆盖说法冲突，请帮我收紧范围并设计镜像问题。”

如果企业、项目或流程编号未知，Skill会标记待创建，不会编造。输出是访谈准备方案，不是诊断报告。

## 你会得到什么

- 一份范围明确的访谈目标与待验证假设；
- 一张按 `P0 / P1 / P2` 排序的角色覆盖矩阵；
- 完整建议覆盖与受时间/人数限制的最小可行组合；
- 待验证的跨角色分歧、镜像问题和最小核对材料；
- 每类角色的开放主问题、模糊回答追问条件和提问理由；
- 与关键问题对应的最小证据清单；
- 录音和材料授权提示、现场不能承诺事项；
- 可交给总档案的 `enterprise_interview_plan` 结构化数据块。

## 前置条件

- [ ] 已安装并能使用 Codex；
- [ ] 至少能说明一个行业、部门、流程或业务问题；确实不知道时可以让 Skill 标注假设；
- [ ] 对拟使用的企业背景和材料有权访问；
- [ ] 真实访谈前由项目负责人确认参与角色、时间和录音/材料授权。

本 Skill 不需要额外环境变量，也不读取 `.env` 或认证文件。

## Troubleshooting

| 现象 | 常见原因 | 处理方式 |
|---|---|---|
| Agent没有使用这个Skill | 目录未安装、会话未重新加载，或提问没有表达“访谈前准备” | 确认入口文件存在，重新开启任务，并直接说“使用企业访谈准备 Skill” |
| 输出变成了通用问卷 | 没有给出具体流程或访谈目的 | 至少补充行业、部门、一个流程/问题和本次要支持的决定 |
| Agent开始推荐Agent或RPA | 任务已越过访谈准备边界 | 要求停止技术选型，将后续交给企业AI流程诊断 Skill |
| 问题数量很多、现场无法使用 | 角色范围过宽或把追问分支全部当成必问 | 收紧到一个流程；主问题用于必问，追问只在回答模糊或证据不足时触发 |
| 企业编号或流程编号被猜测 | 输入缺失且未正确标注 | 要求标为“待创建/待确认”，不得编造标识 |
