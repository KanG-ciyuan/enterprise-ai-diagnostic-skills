# CRM客户授权与归属交接合成诊断

> 诊断性质：E5 AI模拟，待真实企业验证。
>
> 本文只验证 `enterprise-ai-process-diagnosis` 的诊断结构、技术边界和影子试点设计。它不代表真实企业需求、员工事实、管理层批准、系统能力、开发可行性或经营收益；不写入正式总档案，不授权连接或写入生产 OA/CRM。

## A. 内部诊断

### 1. 诊断结论

| 项目 | 当前结论 |
|---|---|
| 主要业务结论 | **建议进入试点** |
| 试点边界 | 仅限3至7天离线影子试点，使用合成或经授权脱敏文件，不连接生产系统 |
| 置信度 | **中**：合成材料对正常路径和异常路径覆盖较完整，但没有任何真实企业证据 |
| 整体技术成熟度 | **可进入离线影子验证** |
| 生产开发状态 | 阻塞：真实接口、权限、字段、测试环境、安全边界、运维责任和验收基线均未确认 |

选择该结论的原因是：当前材料足以检验“输入预检、有效版本、逐行状态、结果对账”这组离线方法能否工作；但所有业务和系统内容均为E5，不能支持生产集成、收益估算或正式流程变更。

### 2. 业务问题重述

- 参与角色：销售申请人、销售负责人、业务运营负责人和CRM管理员，均为模拟角色。
- 触发：岗位异动、客户调整或客户授权申请。
- 当前模拟路径：整理客户清单 -> OA审批 -> 运营核对 -> CRM执行 -> 简单完成回复。
- 主要输出：客户归属或授权变更结果，以及应可追溯的逐客户执行状态。
- 结果使用者：申请销售、接手销售、业务运营负责人和CRM管理员。
- 当前痛点假设：客户编号缺失、名称重复、申报归属冲突、锁定或权限不足、旧版本误用、部分失败无逐行回执、OA完成与CRM完成状态混淆。
- 期望业务结果：先验证能否在不改动生产系统的条件下，可靠暴露异常、固定唯一有效清单并生成逐行对账结果。

本诊断不把“使用AI”“部署Agent”或“自动修改CRM”设为目标。核心问题首先是流程状态、稳定标识、版本和结果回执是否可控。

#### 7.4 状态、异常和控制

- 影子状态：`received`、`validation_failed`、`awaiting_human_confirmation`、`shadow_ready`、`shadow_reconciled`、`stopped`。
- 唯一键：测试中使用`测试批次ID + 行号 + 合成客户编号`；真实唯一键必须等待企业确认。
- 重复和版本：同一输入计算内容哈希；新裁决版本只能新增并显式使旧版本失效，不静默覆盖。
- 异常：缺编号、重复名称、归属冲突、客户锁定、权限不足、旧版本、部分失败全部进入逐行状态，不自动跳过。
- 重试：离线解析最多一次自动重试；结构或规则问题进入人工队列，不循环重试。
- 人工门：归属争议、客户合并、高价值客户、跨部门权限、规则变更和最终验收必须由有权角色确认。
- 审计：记录输入文件哈希、规则版本、每行状态、人工确认人/时间和输出版本；真实保留期限待安全负责人确认。
- 停机：任何非E5真实材料混入、授权不明、敏感信息未脱敏或出现生产写入请求时立即停止本轮测试。

#### 7.5 AI和Agent边界

- AI可做：识别非结构化备注、生成异常摘要、列出证据来源和建议补证问题。
- AI输出必须包含：来源材料ID/行、E5标签、置信度、待人工确认状态。
- 确定性规则负责：必填、字段类型、唯一编号存在性、完全重复、版本、状态和允许值。
- 人工负责：真实客户匹配、归属裁决、合并删除、审批、生产写入和最终验收。
- 本轮不采用可调用生产工具的Agent；因此没有生产工具白名单、写权限或自主执行路径。

### 8. 风险、权限和内部实施建议

| 风险 | 当前控制 |
|---|---|
| 把合成结果当作客户事实 | 所有输出持续标注E5和“待真实企业验证” |
| “建议进入试点”被理解为生产上线 | 每处明确“离线影子、无生产连接、无写回” |
| 模糊匹配导致错误客户 | 只提示人工确认，不自动产生变更指令 |
| 旧附件被误用 | 哈希、版本号、有效状态和人工批准共同控制 |
| 部分失败被“完成”掩盖 | 强制逐行唯一状态和对账结果 |
| 敏感数据进入模型 | 本轮仅使用合成材料；真实材料需另行授权和脱敏 |
| 无人维护 | 生产路线保持阻塞，直到业务、系统、安全和运维负责人明确 |

内部实施建议：本轮只验证可证伪的流程控制假设，不展示生产收益，不销售“自动执行”。如果离线规则连合成异常都无法稳定识别，应先修正规则和输入结构，而不是扩大技术范围。

| 第4天 | 改造方测试人员 + 业务复核者 | 生成唯一有效影子清单、逐客户回执和人工回滚清单 | 版本化执行草稿、结果回执、回滚草稿、审计日志 | 旧版本仍可进入影子执行清单，或异常被静默忽略 |
| 第5天 | 业务、系统和改造方代表（模拟评审） | 重放正常、缺编号、重复、冲突、旧版本、锁定、越权和部分失败场景 | 试点报告、证据缺口、继续/观察/停止决定 | 不能逐行追溯输入、判断、人工确认和输出 |

#### 通过标准

- 每个合成客户行都有且只有一个可解释状态。
- 缺编号、完全重复、归属冲突、锁定、权限不足、旧版本和部分失败均被显式识别。
- 旧版本不会进入唯一有效影子清单。
- 输出逐客户回执、人工确认队列和回滚草稿，并能追溯到来源材料。
- 同一输入和规则版本重复运行得到一致结果。
- 全程不连接、不读取、不写入生产OA/CRM，也不通知外部人员。

#### 观察标准

- 异常可被识别，但人工确认比例、规则稳定性或结果解释仍需优化。
- 合成输入可完成对账，但缺少真实字段和真实流程证据，不能判断生产路线。

#### 停止标准

- 出现真实敏感数据且授权、脱敏或保留边界不明确。
- 需要以名称模糊匹配自动裁决客户或修改主数据。
- 无法保留E5标签、来源定位、版本或人工确认记录。
- 要求在当前阶段承诺ROI、自动化率、节省工时、准确率或生产可用性。

#### 回退

删除本轮影子输出并不改变任何真实业务状态；测试失败时继续使用原人工流程。本轮产物仅保留在本地测试分支，是否进入后续真实验证由用户另行决定。

## B. 客户沟通版

### 当前发现

本轮模拟显示，客户授权与归属交接最值得优先验证的不是“自动点击CRM”，而是四项基础控制：申请清单能否在审批前发现明显问题、争议后是否只有一份有效清单、执行结果能否逐客户反馈、审批完成与CRM完成是否被明确区分。

以上发现全部来自合成材料，尚不是贵公司的真实流程结论。

### 推荐路线

建议先开展5天离线影子试点。试点只使用合成材料或经贵公司授权脱敏的文件，在独立环境中生成预检结果、人工确认队列、唯一有效清单和逐客户对账回执；不连接生产OA或CRM，不修改客户数据。

### 双方责任与前置条件

| 参与方 | 本轮责任 |
|---|---|
| 企业业务负责人 | 确认业务规则、归属裁决人、有效版本和暂停条件 |
| 销售与运营代表 | 提供经授权脱敏的最小样本并核对流程描述 |
| CRM/OA负责人 | 说明字段、导入导出、权限、日志和测试环境条件 |
| 安全负责人 | 确认数据脱敏、模型使用和材料保留边界 |
| 改造方 | 构建离线预检与对账原型，记录证据、异常和测试结果 |

### 本轮不包含

- 不连接、不操作生产OA或CRM。
- 不让AI裁决客户归属、审批责任或客户合并。
- 不承诺ROI、自动化率、节省工时、准确率、上线日期或生产集成能力。
- 不以模拟结果代替真实员工确认和管理层批准。

### 下一决策门

只有当离线影子试点通过，且真实负责人补齐最小业务规则、授权脱敏样本、稳定客户标识、系统接入条件、安全边界和维护责任后，才判断下一步是继续文件型试点、设计只读系统验证，还是停止推进。生产写入需要独立审批，不随本轮试点自动获得授权。
