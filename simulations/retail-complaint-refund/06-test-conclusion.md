# 连锁零售客诉案例：端到端测试结论

## 总结

这次模拟证明，现有三个 Skill 已经能够形成一条有意义的诊断链，而不是三个互不相关的提示词：

```text
困难员工模糊回答
→ 自适应追问与员工确认流程卡
→ 多角色材料证据包
→ 冲突和禁止结论
→ 业务判断与技术可行性
→ 离线影子试点与管理层简报
```

但它仍然是“专业方法原型”，不是可以直接交给企业自助使用的成熟产品。

## 本轮通过的能力

### 1. 困难员工访谈不是固定15问

Agent能针对“处理一下、看情况、系统会有”等回答继续追问：

- 把模糊动作拆成POS查单、退款、发券、群升级和实物交接；
- 把“小金额”追到退款和补偿权限的不同口径；
- 把“店长回复”追到已读、接管和关闭的语义差异；
- 获取真实异常，而不是停留在正常流程；
- 在员工修正后更新流程卡并取得明确确认。

### 2. 证据包有效阻止了过度合并

材料分析保留了五个冲突，没有为了报告流畅而替企业下结论。特别是：

- 没把热线11笔直接认定为漏登记；
- 没把员工口述的50元发券变成正式规则；
- 没把群回复“收到”当作正式接管；
- 没把30分钟上报和24小时关闭目标写成实际达成。

### 3. 诊断结果能落到具体工程对象

技术方案已经具体到：离线导入、统一案件表、规则检查、AI字段提取、人工复核、影子状态机、审计日志和生产连接器，并逐项区分可开发、有条件和阻塞。

### 4. AI与Agent没有被强行加入

AI只负责文字提取和风险线索，赔付、客户承诺、高风险定级和最终关闭仍由人负责。首轮没有为了显得先进而采用自主Agent。

## 本轮暴露的核心缺口

### P0：缺少总控层的正式档案契约

三个 Skill 能人工串联，但尚没有一个总控定义：

- 当前项目处于访谈、补证、诊断还是试点阶段；
- 同一流程的多名员工卡如何版本化；
- 证据包更新后，哪些诊断结论必须失效并重算；
- 内部版、客户版和老板版如何共享同一组结论ID。

这比继续增加访谈问题更重要。

### P0：缺少“组织确认”记录

员工确认只能证明员工自己的说法。跨角色冲突需要另一种正式记录：

- 谁对哪条规则有决定权；
- 最终选定了什么口径；
- 生效时间和版本；
- 哪些历史诊断需要重新评估。

建议下一轮新增的是“业务规则与责任确认单”契约，不一定立刻做成独立 Skill。

### P1：访谈准备仍有独立价值

当前员工摸排适合员工自述，但改造方拜访前仍需要根据行业、部门和岗位生成：

- 角色名单；
- 访谈目标；
- 主问题与追问触发；
- 建议索取的最小材料；
- 不应当场承诺的事项。

这适合成为下一个独立 Skill，但应排在总控档案契约之后或同步设计。

### P1：可视化应读取结构化档案，而不是重新总结报告

老板版图表应直接引用结论ID、冲突ID、组件状态和决策门。否则可视化层可能重新解释文字，造成证据漂移。

本轮已生成可交互可视化片段，但浏览器桌面/手机截图验证因本机Playwright/Chrome环境未成功，必须保留为缺失证据。

### P1：已有人工收件过渡协议，正式隐私与存储能力仍未解决

本轮已补充 `07-manual-intake-protocol.md`：员工确认后导出提交包，由企业指定项目联系人受控收件、登记版本并返回回执；修改形成新版本，不静默覆盖首次提交。这能支持小范围模拟和试点准备，但无法保证员工首次陈述完整，也不等于企业材料平台。

真实入口至少需要：

- 原始提交只追加或保留版本；
- 员工可以更正但不能无痕改写历史；
- 授权撤回与依法删除；
- 项目、部门和角色权限；
- 文件哈希、操作日志和导出记录；
- 改造方只能看授权范围。

这属于未来统一入口的产品与数据治理工程，不能塞进Markdown Skill解决。

## 是否值得继续

值得继续，但应控制投入顺序。

它的价值不在于“AI能生成一份咨询报告”，而在于：让访谈、材料、冲突、业务决策、技术条件和试点之间保持可追溯，减少改造方凭印象或模型想象给方案。

真正的风险是范围无限膨胀：如果同时开发访谈、材料上传、数据库、权限、Agent、可视化、报告和系统集成，很快会变成完整咨询平台。因此下一步仍应围绕档案契约和模拟验证，而不是做统一入口。

## 建议下一步

**优先设计“企业AI诊断总档案 v0.1”契约。**

它至少应统一：

1. 项目、流程、角色和版本；
2. 员工流程卡索引；
3. 材料证据包索引；
4. 冲突、禁止结论和组织确认；
5. 诊断结论与组件可行性；
6. 试点、验收和停止结果；
7. 内部、客户与老板视图的字段权限。

完成这个契约后，再分别封装访谈准备和可视化输出，最终总控 Skill 才有稳定的调度对象。
