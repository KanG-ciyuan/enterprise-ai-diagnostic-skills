# 企业 AI 诊断离线运行模拟器设计

## 目标

把现有总控路由、总档案和 CRM 客户归属交接模拟材料串成一条可重复运行的离线链路，用于验证事件路由、人工门、暂停和恢复是否符合既有契约。

本次只验证控制逻辑，不宣称真实企业效果、模型能力或生产可用性。

## 范围

### 包含

- 读取固定的 E5 模拟项目总档案和事件场景；
- 对每个事件调用现有 `enterprise-ai-diagnostic-orchestrator` 路由器；
- 将已明确授权的模拟结果以只追加方式写入运行日志；
- 演示员工摸排中的材料上传、H1 最小人工确认、S0 授权撤回和项目负责人手动恢复；
- 输出便于人工审阅的运行摘要和最终总档案快照；
- 通过自动化测试验证关键安全边界。

### 排除

- 不调用任何大模型或外部 Agent 平台；
- 不接入数据库、任务队列、账号体系、OA、CRM、企业微信或文件存储；
- 不生成真实员工流程卡，不把 E5 模拟资料升级为 E1-E3 事实；
- 不自动裁决客户归属、责任争议或组织规则；
- 不把流程推进到真实诊断或生产试点。

## 方案选择

采用独立的轻量 Python 运行器。它复用现有总控路由函数，避免在静态报告或单个 Skill 内重新实现调度规则。

不采用纯手工执行，因为无法稳定重放；不采用网页、数据库或 DeepSeek Harness，因为这些会扩大验证范围，并提前绑定尚未稳定的运行底座。

## 运行模型

输入由一个初始总档案和按顺序排列的模拟事件组成。每个事件先经过总控路由，运行器只记录路由结果，并在场景预先声明的人工回执或恢复回执出现时追加新事件。运行器不根据文字猜测下一步，也不自行补齐身份、授权或证据。

```text
初始总档案
  -> 管理层问题提交
  -> 访谈计划确认
  -> 员工任务开始
  -> 员工流程卡确认
  -> 员工摸排中上传授权附件
  -> 材料分析完成
  -> H1 最小人工确认
  -> 授权撤回（S0 暂停）
  -> 项目负责人手动恢复
  -> 等待后续真实补证
```

流程卡确认、材料分析完成和人工确认均只代表固定模拟回执。总控产生的 `scheduling_proposal` 保留原样，运行器不改写其中的正文、证据等级或人工作业说明。

## 数据与状态边界

- 初始档案、输入事件、运行日志和最终快照全部位于 CRM 模拟案例目录；
- 每一条运行日志都包含事件编号、路由决定、目标、原因码、预期返回事件和模拟标记；
- `authorization_withdrawn` 必须产生 `pause`，并建议阶段为 `paused`；
- 只有 `manual_recovery_confirmed` 且角色为 `enterprise_project_owner` 时，场景才允许恢复到预先声明的非生产阶段；
- 恢复后只进入“等待补证”，不得因恢复动作直接越过诊断门；
- 所有生成文件都声明 `evidence_level: E5`、`simulation_only: true`、`production_write: false`。

## 文件设计

新增内容仅限以下边界：

| 位置 | 责任 |
|---|---|
| `enterprise-ai-diagnostic-orchestrator/scripts/run_offline_simulation.py` | 读取场景、调用现有路由器、生成只追加运行记录与摘要 |
| `enterprise-ai-diagnostic-orchestrator/tests/test_offline_simulation.py` | 验证正常路由、人工门、暂停恢复和模拟标识 |
| `simulations/business-operations-crm-authorization/runtime-simulation/` | 初始档案、固定事件、运行输出说明 |

运行输出写入调用方指定目录。默认不覆盖已有输出；如目录已存在，运行器明确失败，避免静默改写历史模拟记录。

## 失败处理

| 情况 | 行为 |
|---|---|
| 输入 JSON 无法读取或缺少企业、项目、事件标识 | 终止运行，输出可读错误，不产生部分结果 |
| 路由事件跨企业、跨项目、来源不明或授权不足 | 保留总控的 S0 暂停提案，不继续后续派生 |
| 场景缺少预期的人工确认或恢复回执 | 停在等待状态，不自动补问、不自动继续 |
| 输出目录已经存在 | 明确拒绝写入，保护旧模拟记录 |

## 验收条件

1. 一条命令能从固定输入生成完整运行记录和人可读摘要；
2. 员工摸排中上传的授权文件路由到材料分析 Skill；
3. H1 事件路由为最小人工确认，不重开完整访谈；
4. 授权撤回后状态为暂停，且不继续派生；
5. 仅项目负责人提供手动恢复回执时可以恢复；
6. 恢复后不自动进入诊断；
7. 自动测试覆盖上述边界；
8. 运行产物始终保持 E5 模拟和不写生产系统标记。

## 后续衔接

这份运行器是未来 Agent 运行层的验收夹具，不是 Agent 平台实现。以后采用 DeepSeek Harness、其他框架或自建轻量运行层时，都应先让新底座通过同一组输入事件和验收条件。
