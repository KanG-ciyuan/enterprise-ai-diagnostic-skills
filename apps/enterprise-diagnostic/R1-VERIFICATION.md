# R1 核验所见版本合同（V0.2）

基线为 `1abb094`；本修复只约束事实首核（相同、不同并修正、证据不足）及独立二核，不扩展发布后主动变更依据的恢复入口。

## 请求与拒绝

核验队列读接口给出的 `evidenceVersion` 是**该事实**的证据版本，`flowCardVersion` 是该事实对应的流程卡版本。前端两种提交均发送原读页对象的这两个字段，不重新取服务器当前值替操作者填入。

两字段必须都是正的 JavaScript 安全整数，与服务端当前事实行相同。缺失、null、字符串、零、负数、小数、布尔值、数组、对象、不安全整数、旧版本和未来版本均不回退为当前版本。拒绝返回 HTTP 409，`code=verification_version_conflict`，明确提示重新加载、审阅并重新判断。原权限及状态门可能在版本校验前先拒绝无权或不适用的请求。

旧客户端无版本的请求会被拒绝。这是有意的安全合同收紧；部署时必须配套更新前后端。本轮没有部署。

## 原子性与审计

初步比较用于尽早返回可理解的冲突。决定是否接受的最终比较位于同一个条件 UPDATE 中：所见事实证据版本、所见流程卡版本、服务端读取的转移键，以及原状态与分配守卫。

UPDATE 和判断历史 / 二核记录 / 任务推进 / 事件仍在原 D1 batch 中。所有后续语句继续要求命中新生成的唯一 `last_transition_key`；条件写入失败时不会产生这些业务副作用。事务报错由既有 batch 回滚。二核事件载荷增加实际所见的两个版本字段，复用现有审计结构，无数据库迁移。

等级更正与影响级别更正是另外的已有专项动作，本轮不改变其权限、状态或并发合同。E3、E5、材料授权与完整性、双核独立性、历史保留和权限门均保留。

## 界面恢复

事实核验提交收到 409 后进入明确的冲突状态，清除旧判断、理由、修正和材料选择，停止提交；页面提供“重新加载最新证据”。只有操作者主动加载后才允许重新判断，不自动刷新带入旧判断，也不自动重试。非冲突的失败保留当前输入。

## 回归与证据边界

- `node tests/r1_verification_version_runtime.mjs`：真实 handler、事务 SQLite，覆盖合法首核/二核、缺失/非法/过期版本、补证、受控并发窗口、竞争写入、零副作用和事件失败回滚。
- `node tests/r1_verification_frontend_runtime.mjs`：执行实际提交函数，检查所见版本载荷、409 后无自动加载/重试、旧判断阻断、500 保留输入。
- 两套加入现有 CI；历史合法测试请求补齐所见版本，原断言保留。缺版本测试不使用旧夹具适配器。
- 实际页面验收、HTTP 请求/响应及数据库前后快照见本任务 `outputs/r1-fix/` 报告；单元测试不等同浏览器或生产验收。

本合同不能证明人类真正阅读了每个字，也不替代材料真实性核验。没有让事实证据版本递增的其他材料变更路径、远端 D1 故障、发布后主动替换材料恢复和生产企业试点不因本修复而视为已验证。
