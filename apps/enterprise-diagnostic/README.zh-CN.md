# 企业 AI 辅助访谈与业务诊断原型

**本目录是 [enterprise-ai-diagnostic-skills](../../README.zh-CN.md) 仓库中的应用原型。**

**状态：本地验证原型 · 非生产就绪 · 尚未经过真实客户验证**

这是一个用于验证 **AI 辅助员工访谈与证据化流程诊断** 的本地原型。访谈由用户发起，由 AI 助手围绕员工的一件具体工作提供提问与草稿辅助；员工本人作答、确认或纠正记录，已确认的记录才可整理成供人审阅的诊断结论。

项目遵循一个基本顺序：**先看证据，再下结论。** 模型可以提出问题和推断建议，但什么算"已证实"，由服务端裁决。

> 本项目不是普通 AI 问卷工具，不是商业化 SaaS 平台，不是可以完全自动改造企业的系统，也尚未经过真实商家、真实企业数据或生产环境的验证。

---

## 项目为什么存在

企业 AI 项目经常先问"该买什么工具"，却没有先确认工作到底怎么发生。这个原型探索相反的顺序：

1. 访谈真正做这项工作的人；
2. 记录员工实际怎么做，包括异常和交接；
3. 保存证据及其历史；
4. 由第二个角色核验高影响事实；
5. 再讨论风险、方案和小范围影子试点。

项目有意保持为**本地原型**，用来验证交互模型、证据模型和安全边界，而不是宣称一个已经完成的商业产品。

## 已实现的能力

### AI 辅助访谈

- 围绕七个维度逐题访谈：`trigger`、`inputs`、`steps`、`judgments`、`exceptions`、`handoff`、`burden`。
- 员工陈述由服务端保存为可追溯的陈述历史，而不只是一段聊天记录。
- 访谈**不是自主访谈**：由用户发起，员工本人作答并确认记录；模型不能把推断标记为已确认，也不能决定什么算事实。
- 模型可以提议追问和候选推断，但不能把推断标记为已确认。
- 自动化测试使用本地确定性模型 stub，不需要真实付费模型调用。

### 证据与确认

- 服务端证据快照：维度摘要、`answersDigest`、证据序号和版本。
- 候选推断带有 `evidenceRefs`、`evidenceVersion`、模板/内容版本和证据哈希。
- 跨维度依赖规则（G14）：推断依赖的证据发生变化时，仅受影响的推断失效；无关推断保持原状态。
- 依赖变化以追加方式进入审计；失效判定变成 stale，未重新确认不得提交。
- 提交由服务端门禁校验：证据一致性、服务端规范卡、判定新鲜度、依赖完整性和提交状态；
- 历史审计只追加，容量上限 fail-closed，不做静默截断。

### 角色与流程

正式流程覆盖四类视角：

| 角色 | 主要职责 |
|---|---|
| 外部改造方 / 项目操作者 | 建项目、登记企业具名授权、邀请成员、管理诊断流程 |
| 员工 | 描述一件真实工作，并确认/纠正证据记录 |
| 核验人 | 审核证据、逐条确认候选事实；高影响事实需要第二名核验人独立确认 |
| 企业负责人 | 审阅已确认事实、风险和影子试点建议，做最终决定 |

已实现的流程区域包括：项目创建、企业授权记录、邀请、材料元数据登记/复核、员工访谈、核验事实、决策包草拟/核验/发布和负责人决策。本地 D1 持久化这些记录。

### 本地演示

- 演示入口提供四种演示身份和合成演示数据，便于本地查看完整闭环。
- 所有演示内容均为合成数据。仓库不包含真实员工访谈、真实材料内容或生产数据库。

## 系统架构

```text
浏览器（原生 ES 模块）
  index.html / app.js / api-client.js / styles.css
        |
        | 同源 fetch
        v
Cloudflare Pages Functions（functions/api/**）
  鉴权 / 项目 / 邀请 / 材料 / 工作项
  Agent 访谈（employee-turn）
  证据与判定门禁（employee-draft、employee-submission）
  核验事实 / 决策包 / 负责人决策
        |
        +--> D1（SQLite；草稿、证据、事实、决策、审计）
        |
        +--> workers/ 中可选的 Queue consumer（授权确认）
        |
        +--> 模型适配层（兼容 DeepSeek 的 HTTP API）
             或自动化测试中的本地 stub
```

关键目录：

| 路径 | 用途 |
|---|---|
| `index.html`、`app.js`、`styles.css` | 静态原型界面 |
| `api-client.js` | 同源 API 客户端与会话处理 |
| `functions/` | Pages Functions API、证据引擎和提交门禁 |
| `schema.sql`、`migrations/` | D1 schema 与向前迁移 |
| `workers/` | 可选的 Cloudflare Queue consumer |
| `tests/` | 运行时与契约测试，包括 G14 验收套件 |
| `scripts/` | 本地开发、静态构建与走查脚本 |
| `wrangler.toml.example`、`.dev.vars.example` | 本地配置模板（不含真实凭据或生产 ID） |

## 本地快速开始

### 前置条件

- Node.js 22+（已在 Node 22.22.3 验证）
- Python 3.11+（可选走查与 Python 契约测试）
- Cloudflare Wrangler 4.x（`npm install -g wrangler@4.127.1`，或等价的本地安装）
- 本原型不需要应用级 `package.json`。

### 启动应用

```bash
cd apps/enterprise-diagnostic
cp .dev.vars.example .dev.vars      # 如需真实 AI 访谈，填入自己的模型凭据
cp wrangler.toml.example wrangler.toml
./scripts/dev.sh
```

打开 `http://127.0.0.1:8788/`。健康检查：`http://127.0.0.1:8788/api/health`。

本地运行数据写入 `.wrangler/state/`（已 gitignore）。删除该目录即可重置本地环境。

> 示例配置使用 `development` 鉴权模式和仅限本地的测试 bootstrap 路径。**不要将这份配置用于公开部署。** 真实 AI 访谈需要模型端点和凭据；界面和演示路径可以在没有生产模型账号的情况下查看，自动化测试则使用本地 stub。

### 可选走查

本地服务运行后：

```bash
python3 scripts/walkthrough.py
```

走查使用合成记录验证正式本地闭环。退出码 0 表示每一步都通过。

### 运行定向测试

```bash
node tests/pilot09c_g14_final_fix_runtime.mjs   # FINAL-F01/F02 定向，无需数据库
node tests/pilot09c_g14_runtime.mjs             # G14 跨维度行为
```

`tests/` 还包含其他运行时和契约套件。本次发布候选的 G14 验收在冻结候选上运行了 **231/231 定向运行时检查**和 **4/4 原 G14 HTTP 场景**；最终验收还独立复跑了两个新增边界场景（3/3）。这是一份**限定范围的验收记录**，不代表仓库中全部测试都通过，也不代表产品通过了生产安全认证。范围与限制见 `ACCEPTANCE.md`。

## 本项目不是什么

- 不是通用 AI 问卷或调查工具。
- 不是已经商业化的 SaaS 平台。
- 尚未经过真实商家、真实企业部署或生产数据验证。
- 不是自主访谈系统：AI 只提供提问与草稿辅助，事实与决策仍由员工及有权人类负责。
- 不是可以自动改造企业、替代有责任的人类决策的系统。
- 不是生产安全认证。仓库有意排除生产部署配置和真实凭据。
- 不是穷尽式诊断模型：一次只覆盖一件工作项和七个证据维度。

## 已知限制

- 材料在原型中只做元数据登记/复核；不包含真实文件上传与内容分析。
- 不连接 OA/CRM/ERP；本地开发不发送真实邮件或通知。
- 鉴权是本地/演示模型；没有自助注册，也没有生产身份提供方。
- 服务端无法证明模型推断的依赖范围在语义上完整；它使用显式规则，并在模型无法提供可信依赖时采取保守的过度失效。
- 保守依赖处理可能比生产产品需要更多重新确认。
- 跨标签页、多用户和高负载行为尚未在生产规模验证。
- 部分历史契约测试已知失败；它们不属于 G14 验收门禁，项目选择披露而不是隐藏。
