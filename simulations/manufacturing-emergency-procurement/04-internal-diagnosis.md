# 企业 AI 应用诊断：内部版本（模拟）

## 1. 首要结论

**先改造原业务流程｜置信度：中**

真实问题不是“缺一个更聪明的 Agent”，而是紧急采购缺少统一案件编号、共同状态、交接验收和例外时限。先把这些业务责任固定下来，再把规则、系统连接和 AI 能力放到各自适合的位置。

## 2. 业务问题重述

- 参与者：生产计划、工艺（待访谈）、采购、采购经理、供应商管理员、仓库、财务应付；
- 触发：排产缺料或临时插单引发紧急采购；
- 当前主线：聊天/OA 发起 → 补资料 → 询价比较 → 经理批准 → ERP 建单 → 到货协同 → 付款资料审核；
- 当前痛点：入口先后不一致、个人表格承载状态、规格责任不清、ERP 可见性争议、紧急批准事后补、付款资料反复补充；
- 目标：每一笔紧急单有唯一记录、责任人、当前状态、待补材料、下一时限和完整证据链。

## 3. 证据与矛盾

| 类别 | 结论 | 等级 |
|---|---|---|
| 样本事实 | 一笔 ERP 订单含申请、供应商、金额、审批、到货等字段 | E1，仅限单笔样本 |
| 多角色一致 | 聊天可能先于 OA；紧急单需要跨生产、采购、仓库、财务协作 | E2（模拟多角色口述） |
| 单角色说法 | 每周单量、操作时间、等待时间、返工量 | E3 估计 |
| 制度预期 | 报价数量、ERP 正式建单、付款附件要求 | E4，未证明每笔实际执行 |
| 关键冲突 | ERP 可见时点、付款资料移交时点、规格责任、聊天批准效力 | 未解决 |

## 4. 需求真实性判断

| 维度 | 当前判断 |
|---|---|
| 重复性 | 有，每周持续发生，但数量仅为估计 |
| 成本与风险 | 等待、退回、漏单和停线风险存在；缺少可量化基线 |
| 流程稳定性 | 常规路径可描述，例外和责任仍不稳定 |
| 数据 | 有 OA、ERP、聊天、报价和附件来源；授权、结构和接口未知 |
| 负责人 | 采购经理可负责供应商决策；跨部门流程负责人尚未明确 |
| 成功指标 | 可定义为状态可追踪、材料一次齐备、异常按时接管、人工时间变化；尚未测量 |

## 5. 最小充分技术路线

| 层次 | 应承担的工作 | 第一阶段边界 |
|---|---|---|
| 业务流程 | 统一紧急单定义、案件编号、责任人、交接验收和时限 | 先由业务负责人确认，不交给模型决定 |
| 确定性规则 | 必填字段、报价数量、金额分支、审批完整性、超时提醒 | 可解释、可审计；规则负责人维护 |
| 工作流 | 管理状态、等待、退回、补件、升级、人工确认和恢复 | 主干能力 |
| API/结构化连接 | 在授权且接口存在时读取 OA/ERP 状态 | 接口和权限未知前不指定产品 |
| AI 工作流 | 从聊天/附件提取申请字段；草拟缺件清单；总结报价差异和异常原因 | 只做理解、分类、摘要和草拟，必须人工确认 |
| 有界 Agent | 在已授权资料中选择下一项“查询或追问”动作 | 暂不进入首轮试点；待工具权限、日志和失败恢复验证 |
| 人工 | 规格正确性、供应商决定、单一来源批准、订单授权、付款放行 | 不自动化 |

### 被拒绝的路线

- **直接上自主 Agent：** 当前责任、接口权限和异常边界未稳定，容易把业务争议变成不可审计的模型动作。
- **纯 RPA 串联系统：** 不能解决规格责任、批准效力和付款验收口径；如有官方 API，应优先 API。
- **只做聊天机器人：** 能回答问题但不能提供共同状态、超时升级和证据链。
- **只做流程图：** 能看清问题，不能验证数据可用性和实际收益。

## 6. 五天影子试点

| 天 | 工作 | 产物 |
|---|---|---|
| 第 1 天 | 选取 20 笔脱敏历史紧急单，定义共同字段、角色、状态与人工基准答案 | 样本清单、字段字典、责任草案 |
| 第 2 天 | 用规则检查必填项、报价数量、审批链和超时；不写回 OA/ERP | 规则命中记录、误报/漏报清单 |
| 第 3 天 | 让 AI 提取聊天与附件字段、草拟缺件清单和报价摘要 | AI 结果与人工结果逐项对照 |
| 第 4 天 | 覆盖规格不全、编码失效、单一来源三个例外，演练人工接管 | 异常路径记录、接管成功率 |
| 第 5 天 | 比较原流程与影子结果，审查权限、维护人和继续条件 | 试点评估、继续/调整/停止建议 |

### 判定标准

- **通过：** 20 笔样本全部形成可追溯案件；高风险缺件不漏报；模型不做供应商选择、批准或付款决定；三个例外都能进入明确人工接管；人工复核后才形成对外结果。
- **观察：** 普通字段存在少量抽取错误但能被复核发现；时间改善方向可见但样本不足；接口条件仍待确认。
- **停止：** 数据未经授权、关键字段无法获得、业务负责人不能统一规则、高风险缺件出现漏报、或无法恢复到原流程。
- **回退：** 全程影子运行，不写回生产系统；停止时继续使用现有 OA、ERP 和人工交接。

## 7. 商务与实施边界

- 现在只承诺完成调研和影子试点，不承诺 ROI、上线日期或自主决策；
- 企业需指定跨部门流程负责人、规则维护人、数据授权人和验收人；
- 实施方负责证据整理、原型配置、测试记录和风险披露，不替企业承担采购与付款责任；
- 下一决策点：六项质疑获得最小证据后，决定是否进入 5 天影子试点。
