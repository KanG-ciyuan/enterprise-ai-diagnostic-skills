# 跨岗位流程卡摘要（模拟）

以下四张卡均为独立记录。合并时只关联相同业务对象，不把不同角色的说法覆盖成一个“统一事实”。

## CARD-PLAN-01：生产计划员发起紧急采购

| 项目 | 内容 | 证据 |
|---|---|---|
| 触发 | 排产缺料或临时插单 | E3 模拟员工确认 |
| 操作 | 先在聊天中催采购，同步准备 OA 申请；补物料规格、需求日期、预算归属 | E3 |
| 判断 | 是否会影响 48 小时内排产 | E3，未见排产记录 |
| 交接 | 把申请编号、物料、数量、最晚到货日给采购 | E3 |
| 异常 | 规格拿不准时找工艺工程师确认 | E3，工艺岗位未访谈 |
| 负担 | 每周约 3-6 个紧急申请 | E3 估计 |
| 角色说法 | “采购建单后，仓库应该能在 ERP 里看到，不需要我再通知” | E3，待仓库确认 |

## CARD-PROC-01：采购专员处理紧急采购

完整流程卡见 `01-difficult-employee-mapping.md`。

| 项目 | 内容 | 证据 |
|---|---|---|
| 触发 | OA 待办或聊天催办 | E3 |
| 非正式记录 | 个人 Excel 防漏单和跟踪待补材料 | E3，文件未提供 |
| 判断 | 价格、交期、历史质量、合格供应商名录 | E3；报价数量规则 E4 |
| 决定权 | 采购经理决定供应商 | E3 |
| 输出 | ERP 订单、订单号、预计到货日、付款资料包 | 单笔 ERP 字段 E1；一般流程 E3 |
| 角色说法 | “建单后会把订单信息发给生产计划和仓库” | E3，待对方确认 |

## CARD-WH-01：仓库收货员准备并执行收货

| 项目 | 内容 | 证据 |
|---|---|---|
| 触发 | 收到采购聊天通知，或供应商车辆到厂 | E3 模拟员工确认 |
| 操作 | 按订单号查询 ERP，核对物料、数量、预计到货日，准备库位 | E3 |
| 判断 | 是否存在可收货订单、物料与送货单是否一致 | E3 |
| 异常 | 供应商先到但 ERP 订单不可见时，联系采购确认，货物暂放待检区 | E3 |
| 负担 | 每周约 2-5 次紧急到货 | E3 估计 |
| 角色说法 | “紧急单经常先收到聊天消息，ERP 里不一定马上能查到” | E3，与生产计划员说法存在张力 |

## CARD-AP-01：财务应付审核付款资料

| 项目 | 内容 | 证据 |
|---|---|---|
| 触发 | 收到采购移交的合同、订单与付款资料 | E3 模拟员工确认 |
| 操作 | 核对采购订单、合同/报价、验收入库和审批依据 | E3；应付清单为 E4（模拟） |
| 判断 | 金额、供应商、订单、验收与批准链是否一致 | E3 |
| 异常 | 缺报价比较或单一来源正式说明时退回采购补充 | E3，无退回日志 |
| 负担 | 采购称资料“建单后交财务”，财务称通常在到货或请款时才收到 | E3 对 E3 冲突 |
| 角色说法 | “聊天同意或截图不能替代最终 OA 审批和付款附件” | E3，需制度确认 |

## 合并输入边界

- 四张卡都保留 `card_id`、来源角色、版本和确认状态；
- 员工确认只证明 Agent 没有误述其回答，不证明该说法对全流程成立；
- 只有一笔 ERP 订单字段达到 E1，其他关键交接仍主要是 E3；
- 改造方只能新增派生诊断，不得静默修改这些卡。
